## 阶段退出条件（§31）

- ☐ **M0 冻结基线与关键平台验证** — 原型在目标 NixOS VM 可复现；明确 Node/Pi/native 二进制与 libc 的构建方法；固定离线安装闭包和机器部署配置生成方案。关键 API 不成立时先修改本规格和对应验收，不用临时旁路把问题藏到后期。
- ☐ **M1 身份契约、机器目录与迁移骨架** — 旧数据 hash 不变；任何客户端自报 UID/workspace/principal 均不能产生权利；重复 provisioning 和跨库强杀可恢复；旧程序拒绝不兼容新库。
- ☐ **M2 独立执行工作区、本地入口与机器准入** — 真实两个 UID 下无法读对方数据/socket；两个并发工作区不会复制模型/构建总额度；machine 重启不重复放槽；事件、日志和收据不串工作区。
- ☐ **M3 成员协作、撤权与根侧协议** — 撤销竞争有明确提交点与 ack，Host/broker 失联时失败关闭；旧 token、旧协议、旧 memberVersion 和旧计划不能派发；共享同一资源不能绕过 quarantine。
- ☐ **M4 原生画布与完整应用操作** — 原生客户端完成 v0.1—v0.4 全部用户主流程；不依赖 WebEngine；任意字符串不能注入 QML/富文本命令；中文输入、工作区切换和晚到事件不泄漏状态。
- ☐ **M5 登录、锁屏、硬件设置与电源** — 无模型也能登录和操作已有应用；锁屏故障不会暴露画面；硬件设置有真实状态核对；睡眠/唤醒不重派外部效果，未支持设备显示准确。
- ☐ **M6 NixOS 镜像与离线安装** — ISO 可独立离线安装并正常登录；qcow2 克隆首启身份各异；磁盘身份变化拒绝执行；安装中断可核对；首次机器配置没有默认密码、faux 或开放调试入口。
- ☐ **M7 签名发布、系统试启动与兼容回退** — 断网/断电不破坏旧启动项；坏候选不会提交 default；兼容回退保留新记录和撤销事实；不可兼容版本明确拒绝；所有写启动项步骤可按 updateId 重入。
- ☐ **M8 备份恢复与 v0.4 迁移** — 同机旧备份不复活授权/旧 outbox；异机无旧物理资源执行资格；恢复中断不启动混合数据；旧 v0.4 内容/版本/收据保持且密钥处理清楚。
- ☐ **M9 压力、安全与实体硬件验收** — 本版关键边界无未关闭阻断问题，100 项 required 条目具有匹配等级的证据；原有回归项通过，既有未支持硬件项仍准确标记。未达到硬件门槛只能保留预览状态。
- ☐ **M10 正式发布候选与交付演练** — 可下载/可验证的完整发布集合与实际 hash 对应，全部验收基于同一固定提交/发行锁定清单，已知限制没有被标为通过，恢复文档在 Shell 不可用时仍可取得。正式签名与发布是后续实现交付步骤，本轮不执行。
