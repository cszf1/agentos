# AgentOS v1.0 — NixOS VM checks (KVM)

All VM checks run on GitHub-hosted runners through `.github/workflows/v1-vm-tests.yml` (public repository,
`ubuntu-latest`, `/dev/kvm` opened by a udev rule). Every check is its own matrix job and can be re-run alone:
Actions → **v1-vm-tests** → **Run workflow** → `test = <name>` (or `all`). A failed job uploads its build and VM
logs as the artifact `vm-<name>-logs`. Results are **KVM VM** evidence only: no real GPU/display, no real input
method, no physical disk, no serial device, no real Wi-Fi.

Run one locally on any x86_64 Linux with Nix (flakes) and KVM:

```
cd os
nix build .#checks.x86_64-linux.<name> -L          # builds the closures, boots the VM(s), runs the script
nix build .#checks.x86_64-linux.<name>.driver -L   # driver only; ./result/bin/nixos-test-driver --interactive
```

Without KVM use the `-tcg` variants where they exist (single vCPU; multi-vCPU TCG guests hit RCU stalls):
`nix build .#checks.x86_64-linux.m2-identity-tcg -L`. TCG runs are far slower and must be labelled "TCG VM".

The O09 drill on one commit is the combination of `m6-install` (ISO install), `m18-o09` (v0.4 import → off-machine
restore), `m7-update` (update with commit/rollback) and `build-repro` (two clean builds compared); the acceptance
report lists the four runs for the same commit.

Expected success output of each job: the step "Run VM check (KVM)" ends with the store path of
`vm-test-run-agentos-<name>` and exit 0. Any `!!! Test "..." failed` line is a failure.

Builds that are not VM checks (run in the same environment):

```
nix build .#agentos-native .#agentos-node .#agentos-shell -L   # shell runs its 9 ctest suites (offscreen) in checkPhase
nix build .#agentos-release -L                                 # unsigned manifest.json, sbom.json, SHA256SUMS
nix build .#agentos-iso -L                                     # installer ISO carrying the release closure
nix build .#agentos-qcow2 -L                                   # VM template: same installer, GPT + ESP + LUKS2 + Btrfs (decision 11)
```

## Needs a physical machine (not accepted by any VM run)

These need hardware that neither the dev sandbox nor a CI runner has. They stay **"需实体机，未验收"**:

- V1-H01 real Intel/AMD GPU from login to canvas; V1-H02 display modes, 100/200 % scaling, hot-plug.
- V1-H04 real wired/Wi-Fi with wrong password and link loss; V1-H05 real audio/backlight; V1-H06 suspend/resume
  on a real device; V1-H07 power drain on real hardware; V1-H08 unsupported real hardware.
- V1-D10 real Fcitx5 composition on a real display (the offscreen IME guard test is not this).
- V1-U01 on a physical disk (the VM install covers the flow on a virtio disk only); V1-U02 with real WWN/serial.
- V3-E04 (inherited) real serial hardware.
- V1-O04/O05 timing on the fixed reference machine.
