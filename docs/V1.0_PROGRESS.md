## 设计决定
1. machined 与 session-gateway 用 Rust（§4.1、§29）。PR #3 的 TS MachineDirectory 作为规则参照，逻辑移入 Rust 后删除 TS 副本，避免两个写者。
2. Host 不监听可被冒充的入口：Host（executionUid）主动连接 root 拥有目录下的 gateway 工作区 socket `/run/agentos/gateway/ws/<workspaceId>.sock`；
   gateway 用 SO_PEERCRED 核对对端 UID == 登记 executionUid；Host 由“路径在 root 目录下”证明对端是 gateway（root）。
   实现：gateway 只有一个 Host 口 `/run/agentos/gateway/host.sock`（目录 root 0755）；machined 只有一个口 `/run/agentos/machine/machine.sock`，按对端 UID 分角色（0=root 客户端；登记 executionUid=该工作区 Host；其余拒绝）。
   结果：Host 的代理入口只可能来自 root gateway（§9.1），普通工作区 UID 无法伪造。
3. Host 内部用 fastify.inject 执行映射后的登记 route，业务处理器复用同一实现（§9.2）。
4. 锁屏：desktop-session agent 运行 swaylock，锁定确认后调用 logind SetLockedHint(true)；gateway 只信 logind 的 LockedHint/Active/Seat/Remote/State。
5. 账户标记写在 GECOS（`agentos-user <provisioningId>` / `agentos-ws <createId>`，不能含冒号）；重放时只接管带同一标记的账户，否则 CONFLICT，不接管既有账户。
6. 机器级 permit 在 Host 的 ModelBudgets.admit 内：本地 permit → 机器 permit（reserved）→ 本工作区最终检查（含发起人 membership_mirror）→ permits.use（memberVersion 必须一致）；结算按 usage 报 used/unknown，绝不退回 unused。
7. 成员撤销：machined 同事务写 revoking + outbox（gateway/host/broker）；Host 应用时停止该成员 run、策略转 paused_needs_review、写 revocation_receipts，然后 ack；三方 ack 齐后才 revoked。
8. Host 机器模式：无 TCP；身份放 AsyncLocalStorage（identityContext），receipt 主体 `user:<userId>:workspace:<workspaceId>`，admit 与提交事务内各查一次 membership_mirror。
9. pnpm：nixpkgs 26.05 把整个 pnpm 10 标为 insecure；覆盖为仓库锁定的 10.34.9，仅构建期使用，用 permittedInsecurePackages 显式放行（不进镜像）。
10. TCG VM 必须单 vCPU（多 vCPU 出现 RCU stall 卡死）；所有 VM 结果标注“TCG VM”。

## 设计决定（续）
11. qcow2 与 ISO 同一发行闭包（§19.1）：`agentos-qcow2` 由 os/packages/qcow2.nix 在构建 VM 里用**同一个安装器**（plan/confirm/run --template）把**同一个 release toplevel** 装到空白 qcow2；布局与实装盘相同（GPT/ESP/LUKS2/Btrfs 子卷）。LUKS 用公开模板密钥（os/modules/template-disk.key，只保护“无身份、无数据”的模板）；initrd 先试模板密钥，不匹配回退口令提示（systemd stage 1）；首启 `agentos-disk-rekey` 在 machined/greeter 之前要求设置新口令并删除模板槽，否则 machined 不启动。已知限制：同一模板的克隆共享 LUKS 卷密钥，需要时由管理员 `cryptsetup reencrypt`（写入 /var/lib/agentos-machine/disk-origin）。旧的 ext4 qcow2 配置已删除。
12. release 改用 systemd stage 1（scripted stage 1 在 26.05 已弃用）；m6 测试此前只在测试变体里开了它。
13. provider worker 账号固定 UID（961–964），NixOS 模块生成 4 个 worker 单元与合法 broker policy（此前 `workers = {}` 使 broker 在所有 VM 里起不来）。发行镜像不登记 lab 网络，network worker 无能力、无网络。
14. 工作区 stop 结束该执行身份的 rootless Podman（podman.socket/service、pause scope、残留容器），否则 fence 检查把 pause 进程当成上一实例（m8 恢复后 attach 报 WORKSPACE_FENCED 的根因）。
15. members.list 按规格 §9.2 表改为 owner 专用。
16. recovery R08 偶发失败根因：tests/proc.ts 每个 vitest worker 用同一随机端口段，两个测试文件可能在同一端口起 Host，后起的绑定失败而 waitHttp 被另一文件的 Host 应答，测试再去读自己从未写出的 auth-token（ENOENT，9ms 失败）。改为按 VITEST_POOL_ID 分段并检查应答时本进程仍存活。
17. 发行镜像未携带 OCI 基础镜像（manifest ociDigests 为空；catalog 基础镜像 docker.io/library/node@sha256:e158… 在首次构建时由 Podman 拉取）——这与 U01“无临时下载依赖”不符，**未解决**，见 ACCEPTANCE_V1.0.md U01 行。

18. 离线 OCI（§19.1，U01/B04/M04）：`agentos-oci`（os/packages/oci.nix）在构建 VM 里用 rootful Podman 对 **与 Host 完全相同的 recipe 上下文**（scripts/release-image-contexts.mjs 逐个核对 catalog recipeHash）`podman build --network=none --pull=never`；基础镜像是固定输出 `skopeo copy --preserve-digests` 的 dir: 副本（manifest 字节不变，digest 校验），npm 只读固定输出缓存（fetchNpmDeps，offline=true）。8 个镜像存成一个多镜像 docker-archive + index.json；release manifest 的 ociDigests 为这些镜像 ID。Host 驱动在需要构建前先看 `AGENTOS_RELEASE_IMAGES`（发行模块 `agentos.releaseImages`），名称与 recipeHash 都匹配才导入到本 UID 的 rootless 存储，导入后再核对 label 与 Env。测试 VM 默认不带（只有发行与需要容器的检查带）。
19. broker 只在机器身份存在后启动：`ConditionPathExists=/var/lib/agentos-machine/machine.secret` + `agentos-broker.path`（首启前 broker 无限等待 machined 身份导致 Type=notify 超时重启，是 m3 失败根因）。
20. 机器级冷备份/恢复编排在 `agentosctl backup|restore`（root）：一个 barrier 冻结整机（barrier 期间 start_workspace 与 host.hello 均拒绝），停止所有工作区后由 recovery-worker 逐个检查点，machine-set.json 的 sha256 作为 manifestHash 完成集合；`backup abandon` 处理中途死亡的备份。restore 走 restores.* 日志（verified→quiescing（control epoch +1）→staging→replacing（每工作区游标）→reconciling（incarnation +1，成员快照对当前目录核对）→complete），中断后保持 restore-in-progress，`--restore-id` 续作。
21. 根侧日志丢失（R11）：machine.sqlite 不在但有旧安装残留（machine.secret/first-boot-id/工作区目录/broker 日志）→ machined 进入恢复模式（不建空库、不开 socket、写 recovery-required），`agentosctl recover --new-identity` 后把残留移入 root-only `lost-<ms>/` 作证据并以新身份启动；broker 若曾 ack 过注册消息（machined status 的 brokerAckedSeq>0）而日志不在 → BROKER_HISTORY_MISSING 仅诊断。
22. m5：virtio-gpu KMS 控制台下仅按键切 VT 不一定拉起 autovt getty → tty_login 显式 `chvt` + `systemctl start getty@ttyN`。
23. Host 机器模式启动前先问 machined（host.precheck），在任何数据库打开之前；barrier/恢复期间 Host 以 75 退出且不触碰数据，systemd 不重启（RestartPreventExitStatus=75）。根因：R02 发现 barrier 下 Host 仍会打开 os.sqlite。m5 在离线检查前删除 user-net 默认路由。
24. 工作区删除（§8.2，W10）：machine.sqlite schema 1→2（规格 §15.1 写的是“设计 schemaVersion=1”；为表达 tombstone 状态必须改 CHECK，故升为 2，迁移单事务、保留全部行；规格文档本身未改）。删除 = 管理员机器操作 workspaces.delete + owner 同意（同一人或 owner 的 workspaces.deleteConsent 操作）；两阶段：deleting → broker 裁决（workspace.deleting 消息，broker 回调 workspaces.deleteVerdict）→ deleted（tombstone）或回 archived。machined 重启时对仍为 deleting 的工作区重新询问 broker。broker 不改 schema：machine_hosts 保持 archived（已栅栏），删除记在 broker_meta `workspace_deleted:<store>`。已知限制：从删除前的旧集合做机器恢复不会自动把已删除工作区复活成 tombstone 以外的状态这一点尚未实现专门检查。
25. 兼容回退（U11）：machine schema 迁移推迟到更新 commit（advance_update→committed 后执行 db::migrate）；试启动期间旧代际仍可接管。releases.setCurrent/known-good 回退先核对目标发行 compatibility 是否覆盖当前数据版本，否则 ROLLBACK_INCOMPATIBLE。本发行 manifest machineSchema=[1,2]。
26. 满盘/只读（R12）：machined storage_guard（statvfs，<256 MiB 或 ST_RDONLY）挡新 permit/工作区/集合/机器操作，错误用规格已有的 MACHINE_CAPACITY；撤权、删除、关机不挡。

27. qcow2 构建 VM（vmTools）挂起根因：stage 1 只装 dm_crypt 及其硬依赖，encrypted-keys 初始化要 cbc(aes) 而 cbc/aes 模块不在列表（`encrypted_key: failed to alloc_cipher (-2)` → dm-crypt "Unknown symbol"），vmTools 里又没有 modprobe 帮手；cryptsetup 在没有 dm udev 规则的 udevd 下等待 udev cookie，`agentos-install run` 静默卡到 110 分钟上限。修复：rootModules 加 cbc/xts/aesni_intel/aes_ti/af_alg/algif_skcipher，构建 VM 设 DM_DISABLE_UDEV=1；模板盘（公开密钥、首启替换）用固定小 KDF 成本。安装器每个外部命令有期限并在 stderr 打进度（复制 90 分钟，其它 10 分钟），卡住时报出命令名。修复后 build-qcow2 约 4 分钟（nixos-install 93 秒）。
28. m6 测试慢的根因不是安装：systemd-ask-password 的提示行不以换行结尾，测试驱动按行读控制台，“assphrase” 要等下一行出现（m6-install 实测 8.5 分钟）；改为每 15 秒键入一次直到出现成功行。另外 m6 断言首启前 `agentosctl status` 成功是错的（身份在 firstboot 创建，之前按设计是 MIGRATION_REQUIRED）；子测试失败时 create_machine 的 VM 不会被驱动回收，nix build 一直等到 CI 上限——现在失败即 crash 该 VM。
29. 机器备份遇到从未启动过的工作区（两个库都不存在）不再整体失败：集合 machine-set.json 的 neverStarted 列出它（没有可恢复的数据；restore/clone 只处理集合里的工作区，它保持原样）。只有一个库存在仍是错误。
30. B01 recovery “偶发失败”根因：测试从不删除临时数据目录，v0.4 验收机 3.9 GiB 的 /tmp tmpfs 积累 830 个目录后写满，后起的 Host 以 ENOSPC 退出。tests/helpers.ts 每个测试文件 afterAll 删除自己建的目录。V4-O05 延迟比值与 recovery 文件并行共享 CPU（podman 构建）会读到 1.38，改为独立串行 vitest 项目 perf（`pnpm test:recovery` 依次跑两者）。修复后 recovery 5/5、perf 5/5（比值 0.97–1.01）。

31. agentos-oci 回归（7960f01 后 m5/m12/m13 构建 VM 内核 panic）根因：Nix 构建环境导出 SOURCE_DATE_EPOCH，podman 5.8 拒绝它与 --timestamp 0 同时出现（“timestamp and source-date-epoch would be ambiguous”），构建脚本 set -e 退出 → 构建 VM init 退出 → panic。修复：podman build 前 `env -u SOURCE_DATE_EPOCH`（f2090b8）。
32. 机器模式代码应用构建全部失败（m12 M04 run 41126604074）根因：10963a0 接入的 Host 构建闸门向 machined 请求 build permit 时 bodyHash 为 `build:<jobId>`，machined 只接受 `sha256:` 前缀，以 INVALID_REQUEST “malformed permit key” 拒绝 → 部署失败 → faux 构建三次 prepare 后 run failed。修复：bodyHash 用 sha256(build:<jobId>)（d88572a）。
33. 沙箱套件 v03-system 7 个连锁失败：见 ACCEPTANCE B01 行（V3-R10 之后 F07 的文件动作使应用连接关闭，rig 无 reconciler 不重启）；根因未定位。

34. 更新提交窗口（U10）：commit intent 记在 machined（updates.commitIntent，写入只追加的 root_audit，仅 validating 可记、幂等；update JSON 带 commitIntent，不改 schema）。`agentosctl update commit`：健康门槛 → intent → worker 写持久 default 并读回 → committed（释放 update barrier，推迟的 schema 迁移只执行一次）。`agentosctl update reconcile` + 开机单元 agentos-update-reconcile（machined 之后、greeter 之前）：machined 事实 + loader 实际启动项 → worker 纯决策 → 执行（进入 validating / 按 intent 重写 default / 完成提交 / 记回退），重复执行无效果。试启动期间 update 持有机器 barrier，任何工作区不能启动（“未提前开放业务”）。测试专用：AGENTOS_TEST_FAULTS=1 下 AGENTOS_FAULT_POINT 与 AGENTOS_TEST_SKIP_HEALTH_GATE（发行单元不设）。
35. session-gateway：会话在活性检查与读取 principal 之间被撤下时返回 SESSION_REQUIRED（原 unwrap 使整个 gateway abort，m13 daily 失败根因）。
36. m15：qemu-vm.nix 以 mkVMOverride 关掉 networking.wireless，NetworkManager 自带的 D-Bus 控制 wpa_supplicant 因此不存在；测试变体用 mkOverride 9 打开（发行配置本来就开着）。m13 测试模型文件用 lib.mkAfter 排在工作区 model.env 之后。

37. v0.4 导入的机器入口（§25 第 2 步）：`agentosctl import-v04 --backup DIR --owner LOGIN`（root）。先在分配任何东西之前逐个核对 manifest 中文件的 sha256 与普通文件类型（IMPORT_HASH_MISMATCH 时什么都不建）；machined workspaces.createFor（origin=imported_v04、storeUUID 取自备份，已登记的 store 以 STORE_ALREADY_REGISTERED 拒绝）分配新执行 UID/账户；工作区停止后把备份私有副本交给该 UID，以该 UID 运行 `agentos-admin import-v04`（Host 侧原有实现：校验、复制普通文件、迁移到 schema 5、内容事实前后比较、user:local 绑定 owner、策略暂停、授权撤销，一次 rename 发布）；收据写在工作区根（root 0600），同一备份重复执行返回 resumed，不再导入。此前该实现只有 Host 级集成测试，机器上没有入口（M01 的证据是真实旧备份的集成测试）。
38. faux 模型的 `[faux:slow:N]` 等待改为响应运行的 abort 信号（取消时在途的 faux 请求立即结束，与真实 provider 流一致）；此前 m13 daily 的取消要等 90 秒 faux 睡眠结束才 reconciled。只影响测试用 faux 模型。

39. broker apply_observation 遇到缺 resource_state 行的资源（管理员在 broker 启动之后登记的单元）先以 generation 1 / unobserved 插入再读取（此前 describe 报 “Query returned no rows”，m17 W09 失败根因）。
40. 原生 Shell 的“可生成”状态以 Host state 视图的 modelAvailable 为准；machine.status 没有 model 组件时不再被当作“可用”（m13 O03：Host 无模型重启后提交按钮仍可用）。
