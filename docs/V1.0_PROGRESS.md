## 设计决定
1. machined 与 session-gateway 用 Rust（§4.1、§29）。PR #3 的 TS MachineDirectory 作为规则参照，逻辑移入 Rust 后删除 TS 副本，避免两个写者。
2. Host 不监听可被冒充的入口：Host（executionUid）主动连接 root 拥有目录下的 gateway 工作区 socket `/run/agentos/gateway/ws/<workspaceId>.sock`；
   gateway 用 SO_PEERCRED 核对对端 UID == 登记 executionUid；Host 由“路径在 root 目录下”证明对端是 gateway（root）。
   实现：gateway 只有一个 Host 口 `/run/agentos/gateway/host.sock`（目录 root 0755）；machined 只有一个口 `/run/agentos/machine/machine.sock`，按对端 UID 分角色（0=root 客户端；登记 executionUid=该工作区 Host；其余拒绝）。
   结果：Host 的代理入口只可能来自 root gateway（§9.1），普通工作区 UID 无法伪造。
3. Host 内部用 fastify.inject 执行映射后的登记 route，业务处理器复用同一实现（§9.2）。
4. 锁屏：desktop-session agent 运行 swaylock，锁定确认后调用 logind SetLockedHint(true)；gateway 只信 logind 的 LockedHint/Active/Seat/Remote/State。
5. 账户标记写在 GECOS（`agentos-user <provisioningId>` / `agentos-ws <createId>`，不能含冒号）；重放时只接管带同一标记的账户，否则 CONFLICT，不接管既有账户。
6. 机器级 permit 在 Host 的 ModelBudgets.admit 内：本地 permit → 机器 permit（reserved）→ 本工作区最终检查（含发起人 membership_mirror）→ permits.use（memberVersion 必须一致）；结算按 usage 报 used/unknown，绝不退回 unused。
7. 成员撤销：machined 同事务写 revoking + outbox（gateway/host/broker）；Host 应用时停止该成员 run、策略转 paused_needs_review、写 revocation_receipts，然后 ack；三方 ack 齐后才 revoked。
8. Host 机器模式：无 TCP；身份放 AsyncLocalStorage（identityContext），receipt 主体 `user:<userId>:workspace:<workspaceId>`，admit 与提交事务内各查一次 membership_mirror。
9. pnpm：nixpkgs 26.05 把整个 pnpm 10 标为 insecure；覆盖为仓库锁定的 10.34.9，仅构建期使用，用 permittedInsecurePackages 显式放行（不进镜像）。
10. TCG VM 必须单 vCPU（多 vCPU 出现 RCU stall 卡死）；所有 VM 结果标注“TCG VM”。

## 设计决定（续）
11. qcow2 与 ISO 同一发行闭包（§19.1）：`agentos-qcow2` 由 os/packages/qcow2.nix 在构建 VM 里用**同一个安装器**（plan/confirm/run --template）把**同一个 release toplevel** 装到空白 qcow2；布局与实装盘相同（GPT/ESP/LUKS2/Btrfs 子卷）。LUKS 用公开模板密钥（os/modules/template-disk.key，只保护“无身份、无数据”的模板）；initrd 先试模板密钥，不匹配回退口令提示（systemd stage 1）；首启 `agentos-disk-rekey` 在 machined/greeter 之前要求设置新口令并删除模板槽，否则 machined 不启动。已知限制：同一模板的克隆共享 LUKS 卷密钥，需要时由管理员 `cryptsetup reencrypt`（写入 /var/lib/agentos-machine/disk-origin）。旧的 ext4 qcow2 配置已删除。
12. release 改用 systemd stage 1（scripted stage 1 在 26.05 已弃用）；m6 测试此前只在测试变体里开了它。
13. provider worker 账号固定 UID（961–964），NixOS 模块生成 4 个 worker 单元与合法 broker policy（此前 `workers = {}` 使 broker 在所有 VM 里起不来）。发行镜像不登记 lab 网络，network worker 无能力、无网络。
14. 工作区 stop 结束该执行身份的 rootless Podman（podman.socket/service、pause scope、残留容器），否则 fence 检查把 pause 进程当成上一实例（m8 恢复后 attach 报 WORKSPACE_FENCED 的根因）。
15. members.list 按规格 §9.2 表改为 owner 专用。
16. recovery R08 偶发失败根因：tests/proc.ts 每个 vitest worker 用同一随机端口段，两个测试文件可能在同一端口起 Host，后起的绑定失败而 waitHttp 被另一文件的 Host 应答，测试再去读自己从未写出的 auth-token（ENOENT，9ms 失败）。改为按 VITEST_POOL_ID 分段并检查应答时本进程仍存活。
17. 发行镜像未携带 OCI 基础镜像（manifest ociDigests 为空；catalog 基础镜像 docker.io/library/node@sha256:e158… 在首次构建时由 Podman 拉取）——这与 U01“无临时下载依赖”不符，**未解决**，见 ACCEPTANCE_V1.0.md U01 行。
